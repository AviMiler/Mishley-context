### 2026-07-19 — ASP.NET Razor support (scan + dependency graph)
- Added: `.cshtml`, `.razor`, and `.json` to `CODE_EXTENSIONS` in `document-handler.js` — Razor views/components and JSON config files are now included in code-project scans (previously only `.cs` was scanned for ASP.NET projects; `.json` config was skipped project-wide for every language, not just .NET). Common noisy JSON files (`package.json`, `tsconfig*.json`, `angular.json`, etc.) stay excluded via the existing `DENY_FILENAMES` list.
- Added: `dep-graph.js#analyzeRazorFile` — Razor/`.cshtml` files now participate in the dependency graph by reusing the C# symbol table (no separate Razor parser): any known class/interface/struct/enum/record name referenced anywhere in the markup (`@model`, `@inject`, tag helpers, embedded C# blocks) becomes an edge to that type's file, filtered by `@using` directives the same way C# `using`s filter ambiguous candidates.
- Added: Razor/HTML comment stripping (`@* ... *@`, `<!-- ... -->`) in `dep-graph.js#scanRegions` (new `lang: "razor"` branch) so commented-out type names don't create false dependency edges.
- Added: Code-behind pairing — `Foo.cshtml`↔`Foo.cshtml.cs` and `Foo.razor`↔`Foo.razor.cs` get a guaranteed bidirectional edge in `buildGraph()`, since Razor Pages/Components split one logical unit across two files that don't necessarily reference each other's type names textually.
- Note: still best-effort like the rest of the C# analysis — doesn't resolve DI-container-injected services, partial view names passed as strings (`Html.Partial("_Foo")`), or `@page`/routing-based navigation.
